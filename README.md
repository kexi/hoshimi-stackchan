# compass-stackchan

M5Stack CoreS3 の公式スタックチャン基板で、**方角を首で指し示す**デバイス。

真北だけでなく、太陽・月・水星・金星・火星・木星・土星の方向を計算し、
yaw サーボで方位を、pitch サーボで高度を、物理的に指す。

「金星」を選ぶと首を回して空の一点を指す。夜に窓からその方向を見ると、
実際にそこに金星がいる。

## ハードウェア

- M5Stack CoreS3
- M5 公式スタックチャン基板 (StackChan-BSP)
- 方位センサは CoreS3 内蔵の BMI270 + BMM150 (追加ハード不要)

顔は公式の [M5Stack-Avatar](https://github.com/meganetaaan/m5stack-avatar)。
描画は Avatar 自身のスレッドが回すので、`M5.Display` へ直接書かない (取り合いになる)。
状態は表情と吹き出しで伝える。首が届かないときは困った顔で、指せない方向へ
目だけを向ける。

吹き出しは幅が文字数で決まり、画面 (320px) からはみ出すと切れる。
右寄せの固定位置でも主語つきの状態文が収まるよう、文字は 8px フォントを
Avatar 固定倍率の2倍で使い、状態文を全角6文字以内にする。地平線下では
「太陽は地平下」のように、対象を省略せず表示する。

## 開発環境

nix devshell + direnv で完結する。`direnv allow` するか `nix develop` に入れば、
必要なツール (PlatformIO / CMake / clang-tools / just / uv / lefthook / gitleaks /
pinact / actionlint) がすべて揃い、pre-commit hook も自動で入る。

```console
$ direnv allow          # または nix develop
$ just                  # レシピ一覧
$ just doctor           # ツールチェーンの実体を確認
$ just test-host        # ESP32 非依存コアのホストテスト
$ just build            # CoreS3 ファームウェアのビルド
$ just update-ephemeris # JPL Horizonsから高精度暦DBを再生成
$ just set-time         # ホストの時計を RTC へ焼き込んで書き込み
$ just watch 30         # 実機の状態をシリアルで 30 秒眺める
$ just verify           # シリアル経由で全8ターゲットを自動検証する
$ just check            # ローカル品質ゲート
$ just ci               # CI と同じ全チェック
```

`just fmt` で整形、`just lint` で clang-tidy。
pre-commit hook は各 just レシピを呼ぶだけで、**整形はせず検査のみ**行う
(hook が勝手に直すと、ステージした内容とコミットされる内容がずれるため)。

## 構成

```
lib/                ESP32 非依存の純 C++17。ホストでテストする
  astro_core/       天体暦 (太陽・月・惑星)、時刻・座標変換
  compass_core/     地磁気キャリブレーション、傾斜補正、測定ゲート
  pointing_core/    天体の方位・高度 → サーボ角度のマッピング
firmware/           CoreS3 側。lib/ を lib_extra_dirs で共有する
test/               ctest から回すホストテスト
```

ロジックを `lib/` に切り出しているのは、天体計算も方位計算も
**実機なしで数値検証できる**ようにするため。CI ではホストテストと
ファームウェアのビルドを両方通す。

## 使い方

初回、またはキャリブレーションが消えたときは「回して N%」と出る。
**CoreS3 を机に置いたまま、水平を保ってゆっくり一回転**させる。持ち上げると
姿勢が変わって採用されないので、机から離さないのがコツ。100% になれば完了。

方位はCoreS3の基板X軸ではなく、**ディスプレイの表側**を顔の正面として扱う。
CoreS3公式軸の `X=画面右、Y=画面上、Z=画面表側` を、スタックチャン用の
`前=Z、右=X、上=Y` へ変換してから傾斜補正とキャリブレーションを行う。
方位角は北を0度として時計回りに増やす。K151実機で北指示と火星指示を比較し、
顔座標の水平磁場を `atan2(Y, X)` へ入れると、物理的な画面方向と一致することを
確認した。一般的なコンパス実装の `atan2(-Y, X)` をそのまま使わない。

完了すると首をいったん正面へ戻して方位を採り、真北を指す。以後も方位測定の
たびに正面・水平姿勢へ戻す。首を横へ振った姿勢の磁気は、yawだけでなくpitchと
磁場強度まで変わるため方位には使わない。

その後は、

- **スワイプ** — 頭のてっぺんを**前から後ろへなぞる**と
  北 → 太陽 → 月 → 水星 → 金星 → 火星 → 木星 → 土星 を順送り
  (タッチセンサは前・中・後の 3 ゾーン。左右方向ではない)
- **タップ** — 起動時ONの自動巡回を ON / OFF

本体が動いたことを検出すると、首を正面へ戻して新しい方位を測ってから指し直す。

画面は表情と主語つきの吹き出しで状態を伝える。首の可動域を超える場合は
「金星はうしろ」「太陽は上すぎ」、見えない場合は「土星は地平下」のように
表示し、黙って端に張り付くことはない。

yaw の可動域は ±128 度しかないので、機体の背後にある天体には届かない。
たとえば機体が北東 (61 度) を向いているとき、南西 (225 度) の金星を指すには
首を +164 度回す必要があり、これは可動域の外になる。**本体ごと回して向きを
変える**と届く。

### Wi-Fi、時刻、mDNS、GeoIPの設定

天体を指すには時刻が要る。起動直後はRTCを使い、Wi-Fi接続時はNTPを正本として
補正する。RTCが既に有効でもNTP同期を省略しない。

```console
$ just set-time     # 書き込み後、ホストの現在時刻を RTC へ同期 (Wi-Fi 不要)
```

`set-time` は書き込み所要時間を予測しない。起動後のCoreS3へUSBシリアルで
その瞬間のUnix時刻を送り、同じ秒の設定完了応答を受け取ってから成功とする。

Wi-Fiを使う場合は `firmware/src/wifi_config.h` にSSIDとパスワードを書く
(雛形は `wifi_config.h.example`、実体は `.gitignore` 済み)。NTPサーバーとGeoIPの
有効・無効、URLも同じファイルで変更できる。NTPが通ればRTCにも書き戻すので、
次回からWi-Fi無しでも動く。

接続するとWi-Fi STA MACアドレスの末尾3バイトから名前を作り、
`stackchan-xxxxxx.local` でmDNSへ登録する。実際の名前、接続、mDNS、NTPの状態は
`just watch` の `host=... wifi=... mdns=... ntp=...` で確認できる。

USBをつながなくても、mDNSで実機を自動発見してWi-Fi経由で対象を選べる。

```console
$ just target moon
$ just target 火星
$ just target saturn stackchan-xxxxxx.local  # 複数台ある場合はホストを明示
```

指定できる名前は `north`、`sun`、`moon`、`mercury`、`venus`、`mars`、
`jupiter`、`saturn`（または北、太陽、月、水星、金星、火星、木星、土星）と0〜7。
明示指定した対象を保つため、自動巡回はOFFになる。

磁気・加速度・ジャイロ、方位、サーボ実角はWi-Fi経由でJSON取得できる。
CoreS3の生軸と顔基準へ変換した軸を同時に返すため、方位の軸違いもUSBなしで
比較できる。校正中は `control.calibrationSamples` と
`control.calibrationCoverage` で一周の進捗も見られる。

```console
$ just sensors
$ just sensors stackchan-xxxxxx.local  # 複数台の場合
```

校正の試行値はファームウェアを書き直さず、Wi-Fi経由で実行中RAMへ設定できる。
次の例は傾き許容角を10度にして、新しい校正セッションを開始する。

```console
$ just calibrate 10
$ just calibrate 10 stackchan-xxxxxx.local  # 複数台ある場合
```

試行値は再起動すると安全な既定値へ戻る。一周中の大量の測定点はPSRAMへ置き、
円周被覆率・半径・残差の条件を満たした小さな補正結果だけをNVSへ保存する。
そのため調整ごとのflashも、高頻度のNVS書き込みも行わない。
NVSはPlatformIOが `0xE000`へ書く補助イメージと重ならない専用領域に置く。

GeoIPはTLS証明書を検証して緯度経度だけを取得し、NVSへ24時間キャッシュする。
取得に失敗した場合は有効なキャッシュ、さらに `location_config.h` の固定位置を使う。
IPアドレス由来の位置は概算なので、正確な設置地点が分かる場合は
`#define GEOIP_ENABLED false` として固定位置を使う方が正確である。またGeoIPが更新するのは
緯度経度だけで、磁気偏角は `location_config.h` の値を使う。遠方へ移動した場合は
偏角も現地の値へ変更する必要がある。

時刻が無い場合は真北のみを指す。「時計が無くても方角だけは分かる」ようにしてある。

## 設計上の要点

### 本体の磁石が地磁気の 6 倍あり、キャリブレーションの方法を選ぶ

実機で測ったところ、ハードアイアン (本体の磁石による直流磁場) が地磁気の
6 倍あった。しかもデバイスを傾けると磁石も一緒に動く。

そのため **8 の字回しは使えない**。球フィットの半径が 169uT (地磁気 46uT の
3.7 倍) になり、地磁気ではなく磁石が回転して描く軌跡を見てしまう。

代わりに **本体を水平に一回転** させて、水平面の円を当てはめる。首を固定して
本体だけ回せば磁石との相対関係が保たれる。コンパスに要るのは水平成分だけ
(方位は atan2 で出る) なので、これで足りる。

実機で確認した値:

| 項目 | 実測 |
|---|---|
| 首を固定したときの方位のばらつき | 1.9 度 |
| 首の角度による方位誤差 | 119 度 (これが支配的) |
| サーボの通電による差 | \|B\| 3.0uT / 方位 2.4 度 (小さい) |
| サーボ停止から方位が収まるまで | 300ms |
| サーボ静止後にジャイロ判定を再開するまで | 500ms |
| サーボの静定精度 | ±8.7 度 |
| 筐体の傾き | 約 52 度 (顔として見やすくするため) |

首の角度による誤差が支配的なので、**測定は必ず首を正面に戻してから行う**。
これがノイズ対策の本体で、サーボ電源を落とす対策 (当初の計画) は不要だった。

最終的に、首が真北から **1.0 度以内** を指すことを実機で確認している。

### 方位は同じ測定姿勢へ戻して採る

一時は首の角度ごとの差を `ServoBiasTable` の16ビンへ学習し、指した姿勢のまま
方位を読む方式を試した。しかしK151実機では、横向きかつ大きいpitchで磁場強度
そのものが大幅に変わった。これはyaw角ごとの方位差では表せず、補正後の値も
物理的な画面方向と一致しなかった。

そのため、方位は必ず正面・水平の同じ測定姿勢で採る。指している間は最後に採用した
機体方位を保持し、本体移動または再測定周期で正面へ戻して測り直す。首を振る姿勢の
値を捨てることで、サーボ磁気を角度モデルで推定するより精度を優先する。

### 一度採った方位は、機体が動くまで持ち続ける

指すために首を振ると磁場が乱れて、その場では方位を測れなくなる。だが機体は
動いていないので、方位そのものは変わっていない。

当初は「いま測れているか」を追尾継続の条件にしていた。すると指した瞬間に
「方位を失った」と判断して測定へ戻り、首を正面に戻し、また指しに行く、という
往復から抜け出せなくなった。採用した方位を状態として持ち、機体が動いたとき
(ジャイロ) と再測定の周期が来たときにだけ測り直す。

CoreS3のIMUは顔側にあるため、サーボ稼働中だけでなく停止直後の慣性振動にも
ジャイロが反応する。サーボが静止してから500msはジャイロを読みも判定もしない。
その余韻を本体が動かされた合図として誤認しないためである。

### 実機の状態はシリアルから読む

`just watch` と `just verify` はシリアル (USB JTAG/serial) を読む。

**NVS 経由では動作中の状態が取れない**。フラッシュの読み出しは esptool の
リセットを伴うので、何度読んでも「起動直後」の値しか観測できない。実際、
Pointing に入って 468ms の値が何度読んでも返り続けた。

`ARDUINO_USB_CDC_ON_BOOT=1` と `ARDUINO_USB_MODE=1` が要る。これが無いと
`Serial` は UART0 へ行き、USB には何も出ない。

ハブ経由だと接続が数秒で切れることがあるが、ファームは動き続けている。
`watch_serial.py` は切れたら開き直して読み続ける。

### タッチセンサのスワイプは前後方向

頭頂部に前・中・後の 3 ゾーン (Si12T, I2C 0x68) があり、その順になぞるのが
スワイプになる。左右方向ではない。BSP は 3 ゾーンの反応時刻の差 (30〜400ms)
で前後を判定する。

### pitch は高度と 1:1 で対応させる

BSP の pitch は `0..900` (deci-degree) で**負値を取れない**。
450 を水平とし、±45 度の範囲を 1:1 で写す。

2:1 に圧縮すれば全高度 (±90 度) を表現できるが、「首が本当にその方向を指す」
という要件を壊すので採らない。届かない範囲は clamp し、UI で明示する。
日本の夏の南中太陽 (70-78 度) は上限を超える。

### 磁気偏角の設定は必須

センサが返すのは磁方位、天体計算が返すのは真方位。内部はすべて真方位に統一する。
日本の偏角は西偏 7-9 度なので、**無視すると 8 度ずれる**。
サーボの分解能 0.3125 度に対して 25 倍で、方位精度 0.1 度の要求からは論外。

観測地と偏角は `firmware/src/location_config.h` に置く (既定は千葉市)。
自分の土地の値は NOAA の計算機から得て設定する。

### 天体計算の精度

2025-01-01から2031-01-01までは、JPL Horizonsが返す地心・大気差なしの
見かけ赤経・赤緯・距離をフラッシュ内DBから4点補間する。月は6時間間隔、
ほかの天体は12時間間隔。現在地の緯度・経度による測心視差と地平座標変換は
実行時に行うため、DBは特定の観測地に固定されない。

4点は「4方向を測る」という意味ではなく、時刻の前後2点ずつを使う局所3次補間。
少ないフラッシュ読み出しで曲率を追え、全保存区間の25%・50%・75%位置を
別クエリで検証した結果が0.001度の上限を満たす固定ステンシルとして使う。
3次補間に必要な最小点数で既に上限を満たすため、点数は増やしていない。

| 天体 | 格子間の全区間検証点数 | JPLに対する最大方向誤差 |
|---|---|---|
| 太陽 | 13,146 | 0.000016891 度 |
| 月 | 26,292 | 0.000044066 度 |
| 水星 | 13,146 | 0.000089601 度 |
| 金星 | 13,146 | 0.000016969 度 |
| 火星 | 13,146 | 0.000016666 度 |
| 木星 | 13,146 | 0.000291590 度 |
| 土星 | 13,146 | 0.000015846 度 |

検証点は各保存区間の25%、50%、75%位置をJPLへ別途問い合わせた値で、
生成器は方向誤差が0.001度を超えるDBを出力しない。さらに別の37日間隔の
格子外スナップショットを生成物へ固定し、通常のホストテストでも全7天体を検証する。

DBは約1.6MBのC++生成ファイル、ファーム内では約421KBの読み取り専用データになる。
CoreS3のネット接続は不要。`just update-ephemeris`だけがJPLへ接続する。
生成スクリプトはPEP 723メタデータを持ち、`uv run`でPython 3.11以上の条件を
再現する。Python依存パッケージはなく、HTTPS取得にはdevshellの`curl`を使う。

DB期間外またはデータ不正時は、太陽・月をMeeusの短縮式、惑星をJPLの
1800～2050年向け近似ケプラー要素で計算する。Meeusの例題
12.a / 12.b / 13.a / 13.b / 22.a / 25.b / 47.a / 33.a は
フォールバック経路も含めてホストテストで検証している。

月は周日視差 (最大 1 度) の補正が必須。入れ忘れると月だけずれるが、
他の天体は正しいので発覚しにくい。テストで明示的に担保している。
