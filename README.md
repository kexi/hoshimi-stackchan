# compass-stackchan

M5Stack CoreS3 の公式スタックチャン基板で、**方角を首で指し示す**デバイス。

真北だけでなく、太陽・月・水星・金星・火星・木星・土星の方向を計算し、
yaw サーボで方位を、pitch サーボで高度を、物理的に指す。

「金星」を選ぶと首を回して空の一点を指す。夜に窓からその方向を見ると、
実際にそこに金星がいる。

## ハードウェア

- M5Stack CoreS3
- M5 公式スタックチャン基板 (StackChan-BSP)
- 方位センサは CoreS3 内蔵の BMI270 + BMM150 (追加ハード不要)

## 開発環境

nix devshell + direnv で完結する。`direnv allow` するか `nix develop` に入れば、
必要なツール (PlatformIO / CMake / clang-tools / just / lefthook / gitleaks /
pinact / actionlint) がすべて揃い、pre-commit hook も自動で入る。

```console
$ direnv allow          # または nix develop
$ just                  # レシピ一覧
$ just test-host        # ESP32 非依存コアのホストテスト
$ just build            # CoreS3 ファームウェアのビルド
$ just upload           # 書き込み
$ just monitor          # シリアルモニタ (CoreS3 の USB シリアルだけを掴む)
$ just all              # CI と同じ全チェック
```

`just fmt` で整形、`just lint` で clang-tidy。
pre-commit hook は各 just レシピを呼ぶだけで、**整形はせず検査のみ**行う
(hook が勝手に直すと、ステージした内容とコミットされる内容がずれるため)。

## 構成

```
lib/                ESP32 非依存の純 C++17。ホストでテストする
  astro_core/       天体暦 (太陽・月・惑星)、時刻・座標変換
  compass_core/     地磁気キャリブレーション、傾斜補正、測定ゲート
  pointing_core/    天体の方位・高度 → サーボ角度のマッピング
firmware/           CoreS3 側。lib/ を lib_extra_dirs で共有する
test/               ctest から回すホストテスト
```

ロジックを `lib/` に切り出しているのは、天体計算も方位計算も
**実機なしで数値検証できる**ようにするため。CI ではホストテストと
ファームウェアのビルドを両方通す。

## 設計上の要点

### サーボの磁気ノイズがこのプロジェクトの中核課題

BMM150 は本体基板上にあり、サーボは至近距離にある。首を振りながら測ると
コイル電流の作る磁場が地磁気 (日本で約 46uT) に乗って方位が破綻する。
4 層で防御する。

1. **測定ゲート** — サーボ静止 + settle 後のみ採用。ジャイロで機体の動きも見る
2. **|B| 異常検出** — 静穏時の基準値から外れたら棄却 (保持電流を検出)
3. **測定中のサーボ電源 OFF** — `setServoPowerEnabled(false)` で電流をゼロに
4. **yaw 角度依存バイアス表** — 磁石の位置による静的バイアスを 16 ビンで学習

層 3/4 の要否と settle 時間は、実機での実測 (段階 8) で決める。

### pitch は高度と 1:1 で対応させる

BSP の pitch は `0..900` (deci-degree) で**負値を取れない**。
450 を水平とし、±45 度の範囲を 1:1 で写す。

2:1 に圧縮すれば全高度 (±90 度) を表現できるが、「首が本当にその方向を指す」
という要件を壊すので採らない。届かない範囲は clamp し、UI で明示する。
日本の夏の南中太陽 (70-78 度) は上限を超える。

### 磁気偏角の設定は必須

センサが返すのは磁方位、天体計算が返すのは真方位。内部はすべて真方位に統一する。
日本の偏角は西偏 7-9 度なので、**無視すると 8 度ずれる**。
サーボの分解能 0.3125 度に対して 25 倍で、方位精度 0.1 度の要求からは論外。

自分の土地の値は NOAA の計算機から得て設定する。

### 天体計算の精度

| 天体 | 手法 | 実測誤差 |
|---|---|---|
| 太陽 | Meeus ch.25 低精度式 + 主要摂動 | 黄経 < 0.0001 度 |
| 月 | Meeus ch.47 (ELP2000-82 短縮版) | 黄経 < 0.0001 度、距離 < 0.1km |
| 惑星 | JPL 線形近似ケプラー要素 | 大円距離で約 0.1 度 |

Meeus の例題 12.a / 12.b / 13.a / 13.b / 22.a / 25.b / 47.a / 33.a を
ホストテストで検証している。

VSOP87 フルなら惑星も 1 秒角級になるが、係数表が数千行になり割に合わない。
サーボの分解能が 0.3125 度なので、この誤差は機械側に埋もれる。

月は周日視差 (最大 1 度) の補正が必須。入れ忘れると月だけずれるが、
他の天体は正しいので発覚しにくい。テストで明示的に担保している。
